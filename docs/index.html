      System design

      An @mention is a distributed system with a three-second front door.

      Everything here exists because the chat platform retries any event it thinks you dropped, using the same event id. Split at that deadline and the rest follows: what you can no longer do synchronously has to become a queue, and what a queue makes possible is a team of agents rather than one prompt.

      How to read these diagrams

      Every diagram on this page uses the same three shapes, so what exists and what is proposed can be told apart at a glance rather than from a caption.

      Data flow

      One mention, end to end. Everything below ack happens after the platform has already been told 200 OK.

      Who does what

      Each agent owns exactly one decision. An agent that owns two decisions is two agents that have not been separated yet.

      Orchestration is a graph, not a script

      Five nodes, not nine. Planning and executing were separate until it became clear that is the model's own tool-calling loop, hand-rolled with worse adaptivity — LangGraph is here for the checkpointer and interrupt(), not for node count. The crash-and-resume behaviour is the checkpointer. The tool-approval gate is an interrupt. Neither is bespoke machinery here.

      The retry ceiling and the graph checkpoint are the same idea at two altitudes.

      The queue guarantees a run is attempted; the checkpointer guarantees an attempt resumes where it stopped rather than from the top. Without the second one, a crash in reviewer re-runs every tool call before it — which is slow, expensive, and in the case of a write tool, wrong.

      If it isn't traced, it didn't happen

      LangSmith turns each run into a tree of spans with latency, tokens and status. That is the difference between "the bot said something odd" and "the librarian returned four memories, two of which were stale, and the planner anchored on the wrong one".

      The turn, as a conversation between agents

      The agent adapts one tool call at a time; the verifier is a mechanical gate, not a second opinion.

      Memory

      The part that is a security boundary rather than a feature.

      The scope filter belongs in the query predicate, never after retrieval.

      Post-filtering leaks through result counts, ranking behaviour and latency, and it sits one refactor away from being deleted by someone who reads it as a redundant guard. Scope is derived from the inbound event's channel binding — never from anything in the request body, because in a public channel the request body is attacker-controlled.

      Reaching a tool vs. reaching an agent

      Two problems that look alike and are not. MCP is a typed call into a capability you own. A2A is a task handed to something with its own goals, its own model and its own lifecycle.

      Stack
